# AI Audit Industry Scanner — 산업 이해 기반 감사 Risk Scanner (MVP)

> 기업의 산업·공시정보를 입력하면 **산업 브리핑 → 위험신호 → 확인절차**를 생성하는 감사 보조 도구.
> AI는 위험 **후보**를 제시하고, 판단은 감사인이 한다.

## 실행

```bash
pip install -r requirements.txt
streamlit run app.py
```

- **데모 모드**: API 키 없이 가상 기업 2곳(건설·반도체)으로 바로 동작
- **OpenDART**: 환경변수 `DART_API_KEY` 설정 후 실제 기업명 입력
- **Claude 분석**: 환경변수 `ANTHROPIC_API_KEY` 설정 후 사이드바에서 켜기 (끄면 AI 없이 키워드 추출 + 지식베이스만 쓰는 오프라인 기준선)
- 테스트: `pytest -q tests`

## 실제 기업 검증 (2026-11-13, OpenDART · 오프라인 모드)

| 회사 | KSIC | 적용 산업 | 결과 |
|---|---|---|---|
| 삼성전자 | 264 | 반도체 (같은 중분류 + 본문 55회 확인 규칙) | 특성 5/5 확인, 세전이익 기준 중요성 2.47조, 대주주 거래 구간이 길어 '일부만 읽음' 표시 |
| 신세계 | 47111 | 백화점·면세 (**초안**) | 특성 6/6 확인, 세전이익 기준 중요성 66억 |
| LG에너지솔루션 | 28202 | 2차전지 (**초안**) | 특성 3/6 확인, 유형자산 증가율−매출 증가율 +14.0%p 확인 신호, 대주주 거래 구간 못 찾음 |

실제 공시로 돌려 보고 고친 것:
- **보안 게이트 오탐**: 공시 본문의 '영업기밀'이라는 단어 때문에 삼성전자 사업의 내용 전체가 차단됐다. 이제 보안 게이트는 사용자 업로드 자료에만 적용한다.
- **엉뚱한 사실 문장**: 특수관계자 구간의 계열사 목록이 '사업 구조'로 뽑혔다. 이제 사업 구조·특성은 사업의 내용에서만 찾는다.
- **근거 문장 품질**: 표 제목이나 조각, 범용어('총액', '적립')가 근거로 잡혔다. 이제 완결된 서술문만 근거로 쓰고 키워드를 좁혔다. 오프라인 모드의 근거에는 '관련성은 감사인 확인 필요'를 표시한다.
- **특수관계자 주석 잘림**: 8,000자에서 잘라 '주석에 없음'으로 오탐할 위험이 있었다. 이제 4만 자까지 읽고, 잘리면 '없음' 결론 대신 확인 질문을 만든다.
- **지식베이스 밖 업종**: 3곳 중 2곳이 공통 영역만 나왔다. 삼성전자는 같은 중분류 규칙으로 해결했고, 백화점·면세와 2차전지 산업을 **초안**으로 추가했다.

남은 한계: 오프라인 모드는 키워드가 맞는 문장을 찾을 뿐, 그 문장이 특성의 근거인지는 판단하지 못한다(예: '해외 지역총괄' 문장이 외화환산 근거로 잡힘). 이것은 Claude 모드로 비교해야 한다.

## 화면 구성

- **기업 분석** (첫 화면): 공시 수집 → 특성 확인 → Risk Map → 확인 질문 → 재무 신호·중요성 → 특수관계자 교차점검 → 검증
- **참고 · 산업 이해**: 산업 깊이 보기, 산업 목록. 기업 분석 결과에서 '이 산업 더 보기'로 넘어온다.
- 보류: 본부별 산업, 산업 비교 (파일은 남겨 둠). 본부 구분에 작성자 추정이 섞여 있어 숨겼다.

## AI가 하는 것 / 하지 않는 것

| AI가 하는 것 | 시스템이 강제하는 방법 |
|---|---|
| 사업구조 요약, 특성 **후보** 선택, 회사 특화 질문 **제안** | 구조화 출력(JSON Schema)으로 응답 형식 고정 |

| AI가 하지 못하는 것 | 강제 장치 |
|---|---|
| 지식베이스에 없는 산업 특성 만들기 | 스키마의 `enum` + 가드레일 G5 이중 차단 |
| 계정과목·경영진 주장 연결 | `risk_map.py`가 **검토된 지식베이스(`knowledge/industry_kb.yaml`)에서만** 가져옴 |
| 출처 없이 '사실'이라고 말하기 | G1·G2: 존재하지 않는 출처 제거, 회사 원자료 인용 없는 FACT 강등 |
| 원문에 없는 수치 만들기 | G2: 수치 단위로 원문 대조, 불일치 시 UNVERIFIED |
| "위험하다", 감사의견, 적정성 판단 | G4: 단정 표현 탐지 → 경고 표시, 질문은 제외 |
| 문서 속 지시문 따르기(프롬프트 인젝션) | 원문은 `<source>` 태그 안 데이터로만 취급하도록 지시 |

가드레일은 내용을 **고쳐 쓰지 않는다.** 강등하거나 경고를 붙여 감사인이 보게 할 뿐이며, 모든 조치는 '처리 로그' 탭과 브리핑의 'AI 통제 로그'에 남는다.

## ⑤ Financial Signals — 계획단계 분석적 절차 (`scanner/finance.py`, `fin_view.py`)

Risk Map에서 도출한 계정의 **숫자가 실제로 어떻게 움직였는지** 보여준다 (감사기준서 520).

- **숫자**: OpenDART 단일회사 전체 재무제표 API(`fnlttSinglAcntAll`) 3개년 원본. 연결 우선, 없으면 별도.
- **계산**: 전부 코드. AI는 재무 숫자를 읽지도 계산하지도 않는다.
- **지표·기준**: 지식베이스의 각 위험 항목 `metrics`에서만 정의 (예: 건설 진행률 수익인식 → 계약자산 ÷ 매출, 전년 대비 +5%p 이상이면 확인 신호).
- **연결**: 기준을 넘은 지표는 Risk Map 카드에 `📈 재무 신호`로 표시되고, 실제 숫자를 채운 확인 질문이 `재무 신호` 배지로 추가된다.
- **표현**: 좋음/나쁨 색칠 없이 중립색, 기준을 넘은 지점만 주황색. 문구는 "이상"이 아니라 "확인 신호".
- 회전일수는 기말잔액 기준(평균잔액 아님). 계정을 찾지 못하면 신호를 내지 않고 '계산 불가'로 표시한다.

## 계획 중요성 (감사기준서 320, `scanner/materiality.py`, `mat_view.py`)

재무 신호는 비율의 움직임만 본다. 계획 중요성은 그 움직임이 **금액으로 중요한지**를 붙인다.
- **기준 제안**: 세전이익이 양수이고 안정적이면 세전이익 5%를 제안한다. 손실이거나 전년 대비 50% 이상 변동하면 매출 1%를 제안한다. 초도감사이거나 계속기업 신호가 있으면 수행 중요성을 75%에서 50%로 낮춰 제안한다. 비율은 실무 범위의 예시값이며 지식베이스에서 바꾼다.
- **감사인이 결정**: 기업 분석 화면 상단 패널에서 기준과 비율을 바꾸면 Risk Map·재무 신호·특수관계자·브리핑에 바로 반영된다. 브리핑에는 제안 근거와 감사인 변경 여부가 함께 남는다.
- **비교 금액 = 기대치 대비 차이** (감사기준서 520): `기대치 = 전년 분자 × (당기 분모 ÷ 전년 분모)`, 즉 전년 비율이 유지됐다면 있었을 금액이다. 계정 증감을 그대로 쓰지 않는다. 매출이 늘어 원가가 같이 는 것은 차이로 보지 않기 위해서다.
- **수준**: 계획 중요성 이상 / 수행 중요성 이상 / 명백히 사소한 금액 초과 / 명백히 사소함. 절대값으로 비교하고, 기준 '이상'이면 해당 수준이다. 왜곡표시 판단이 아니라 확인할 곳의 크기를 나타낸다.

## 계속기업 지표판 (감사기준서 570)

재무 신호가 '전년 대비 변동'을 본다면, 지표판은 **수준**을 본다. 자본잠식, 부채비율(200/400%), 영업손익, 영업활동현금흐름의 4항목이며 항상 4개가 같은 순서로 나온다.
- 정보가 없으면 **'정상'이 아니라 '확인 필요'**로 표시한다. 자본이 0 이하이면 부채비율은 계산하지 않는다.
- 주의·위험이 하나라도 있으면 Risk Map에 '계속기업 가정 관련 사건·상황 검토' 영역이 추가된다.

## ⑥ 특수관계자 교차점검 (감사기준서 550, `scanner/related_party.py`)

같은 사업보고서 안의 두 기재, 즉 본문 'X. 대주주 등과의 거래내용'과 재무제표 주석 '특수관계자'를 비교한다.
1. **추출 (AI)**: 표를 옮겨 적기만 한다. 각 행마다 원문 인용(quote)을 같이 낸다.
2. **인용 검증 (코드)**: 인용문이 원문에 글자 그대로 없거나(공백 차이는 허용), 거래상대방·금액 등의 값이 인용문 밖에 있으면 제외하고 사유를 남긴다.
3. **교차 비교 (코드)**: 거래상대방·거래 유형·관계·금액을 비교한다. 금액은 표의 단위(원·천원·백만원·억원)를 환산해서 비교하므로 4,200억원과 420,000백만원은 같다고 본다.
4. 한쪽 추출이 실패하거나 미실행이면 '불일치 없음'이 아니라 **'확인 필요'**로 표시한다. 불일치마다 확인 질문(`교차점검` 배지)이 특수관계자 영역에 붙는다.
- 데모의 '데모 고정 응답'은 API 키 없이 흐름을 보여주려고 미리 기록한 추출 결과이며 AI가 만든 것이 아니다. 일부러 잘못 만든 2건(인용 날조, 인용문 밖의 금액)이 실제로 제외되는 것을 볼 수 있다.

## 그 밖의 보강

- **FACT는 인용문 필수**: 사실로 표시하려면 근거 문장이 원문에 글자 그대로 있어야 한다. 인용이 없으면 Inference로 낮추고, 원문에 없는 인용이면 Unverified로 낮춘다. 수치는 근거 문장 안에서 대조한다.
- **AI 실패 시 대체**: AI 분석이 실패하면 앱을 멈추지 않고 오프라인 기준선으로 대체한 뒤 '확인 필요' 경고를 띄운다. 질문 생성이 실패하면 지식베이스·재무 질문만 보여준다.
- **감사 유형**: 초도감사를 고르면 기초잔액(감사기준서 510) 검토 영역이 추가된다.
- **자료 최신성**: 재무자료가 오래되었거나 사업보고서와 기준연도가 다르면 경고한다.

| 실무 활용성 | 평가자가 결과만 보고 추가 확인 질문 3개 이상을 선택 | ⑦ 검증 탭 Actionability 점수 |

## 결과의 세 가지 유형

- **Fact** — 회사 공시 원문에 직접 근거 (청크 ID 표시)
- **Industry Inference** — 산업 특성에서 도출, 확인 필요 (산업자료 또는 지식베이스 근거)
- **Unverified** — 현재 자료로 확인 불가

검토 우선순위(🔴🟠🟡)는 **위험평가 결과가 아니라 '어디부터 검토할지'에 대한 제안**이다. 회사 공시로 확인된 특성은 지식베이스 기본 순위, 산업자료로만 뒷받침되면 한 단계 낮춘다. 감사기준서 240의 상시 고려 영역(수익인식 부정위험 추정, 경영진 통제 무력화)은 산업 판단과 분리해 항상 표시한다.

## 검증 방법 (`eval/`)

동일 기업에 대해 (A) 사업보고서·산업자료를 직접 읽은 결과와 (B) MVP 결과를 같은 루브릭으로 채점한다.

| 지표 | 질문 |
|---|---|
| Completeness | 주요 산업 특성을 빠뜨리지 않았는가? |
| Relevance | 감사와 관련된 위험을 제대로 찾아냈는가? |
| Evidence | 각 주장에 근거가 있는가? |
| Accuracy | 원자료와 일치하는가? |
| Actionability | 감사인이 다음에 확인할 질문·자료를 얻을 수 있는가? |
| Hallucination | 근거 없는 위험을 만들어내지 않았는가? |

권장 절차: 평가자 2명 이상, 기업 3곳 이상(지원 산업별 1곳), 직접 조사를 먼저 한 뒤 MVP를 보아 순서 효과를 줄일 것. 소요시간도 함께 기록한다.
자동 지표(출처 부착률, 강등 건수, 단정 표현 건수 등)는 '검증' 탭에서 실행마다 계산된다.

## 한계와 확장

- 지식베이스는 3개 산업(건설·반도체·가맹/유통)만 다룬다. 산업 추가 = YAML 추가 + 감사인 검토.
- 오프라인 모드의 특성 탐지는 키워드 기반이라 표현이 다르면 놓친다(예: "원가율이 상승" vs 키워드 "원가율 상승"). Claude 모드와의 차이를 검증 탭에서 비교할 수 있다.
- **Phase 3(비공개 감사자료)은 의도적으로 구현하지 않았다.** 확장 시 데이터 보존·위탁 처리 계약, 접근 통제, 고객 동의가 선행되어야 한다.
- 데모 데이터(`sample_data/`)는 실존 기업이 아닌 가상 예시이며 수치는 임의로 작성됐다.
